# MD助手

Windows x64《游戏王 Master Duel》公开情报记录与联栗炮计算助手。

当前版本：0.3.2。包含新卡资料自动更新、公开手牌离场追踪修复和对方已知顶牌浮窗。

## 启动

直接双击单文件 EXE，无需安装 Node.js、pnpm 或 Codex。首次启动会自动展开运行文件，后续复用缓存；请保留完整 EXE，不要从运行缓存中单独复制 Electron 程序。

启动后进入设置主界面。关闭主界面仅隐藏窗口，程序继续在托盘运行；点击托盘重新打开，从托盘菜单退出助手。重复启动会打开已有主界面。

默认使用自有只读后端，无需 Untapped.gg。仅支持已适配的游戏版本，游戏更新后可能需要重新适配。

## 卡组准备

在支持的排位或活动准备页选择卡组。卡组状态图标显示在卡组区域，鼠标悬停可查看卡组名称、读取状态和主卡组／额外数量。只有当前卡组与版本匹配、所需属性完整时才显示“准备好决斗了”。

首次缺少卡表时，可进入游戏内牌组编辑页读取，再返回准备页。版本不匹配的缓存不会自动当成当前卡表；可在助手主界面核对。状态图标位置按参考截图校准，窗口布局变化时仍可能需要调整。

## 显示与设置

所有调整集中在主界面。信息侧栏只展示数据，不提供设置入口。

| 模块 | 信息内容 | 场上独立浮窗 |
| --- | --- | --- |
| 双方手牌与场上合计 | 总数及对方等级／阶级 | 无 |
| 联栗炮方案区 | 当前可用材料和目标组合 | 无 |
| 已在除外区的联栗炮组件 | 已确认的表侧材料 | 无 |
| 对方已公开手牌 | 卡名、类别与数量 | 可选怪／魔／陷文字或卡图缩略图 |
| 对方盖放魔陷情报 | 盖放位置及公开候选 | 已确认或单一候选显示缩略图 |

设置按侧边栏、公开手牌、盖牌、信息悬浮窗、读取与启动分组。“显示在侧边栏”开关集中在侧边栏组；场上浮窗开关、手牌样式和盖牌偏移在各自模块中调整。开关与手牌样式即时保存，其他参数点击底部“保存设置”。低频读取参数与诊断位于“高级与诊断”。侧栏按开启顺序排列，关闭再开排到末尾；高度随实际内容变化，达到最大高度后滚动。全部模块关闭时侧栏自动隐藏；点击侧边栏组的“显示”会在空选择时恢复默认模块。

信息悬浮窗有独立总开关。悬停入口展开内容，点击入口选择模块；内容按选择先后排列，可同时显示多个模块。它的模块选择与场上浮窗开关互不影响。

开启联动启动 Untapped.gg 后，助手会先检查其是否已运行（包含后台运行）；已运行时不会再次启动。若无法检查运行状态，会显示提示并跳过本次联动。

对方匿名离手（例如里侧放置怪兽）后，无法确认仍在手中的公开记录保留为候选，手牌浮窗标注“可能”，不表示已确认当前卡位或身份。浮窗优先显示确定记录，最多显示当前手牌数量的条目；完整候选可在信息悬浮窗中查看。

公开手牌修复：公开手牌作为融合素材送墓时按逐张公开移动移除记录；有明确普通盖放证据的魔陷盖放不会降低已知怪兽的确定性，效果盖放或证据不足时仍保留不确定性。支持“杀手旋律・绮悠”的中文公开日志：两张展示、其中一张除外、明确选择卡组顶端后，记录剩余顶牌并在对手抽到时转入手牌。洗切、顺序变化或无法判断的效果会清除顶牌推断；抽牌日志延迟到达时会去重。此功能已包含在 0.3.2 EXE 中。

盖卡没有任何公开候选信息时，不显示场上提示。单一候选卡图标注“可能”，不等同于已确认身份。场上盖牌提示采用小尺寸、位于牌面中央，点击提示查看详情，点击四周露出的游戏牌面进行选牌；盖牌详情与多个候选也可从信息悬浮窗的盖牌模块点击查看。手牌提示仍可点击查看详情，是已知手牌清单，不保证洗牌后的真实卡位。

工作区版本会在公开手牌模块单独显示已确认的对方顶牌，不计入已确认手牌张数；抽入手牌或顶牌证据失效后移除该提示。萝塔丽等临时公开手牌效果需要助手在展示期间持续运行，已关闭的展示且未留逐卡日志时无法事后恢复身份。

已确认的对方顶牌也会在对手主牌组区显示卡图浮窗，沿牌组区倾斜，采用手牌缩略图样式，点击查看详情。它与“公开手牌悬浮窗”共用开关，固定显示卡图；抽入手牌后移至手牌记录。浮窗随游戏窗口移动和缩放，透明角落不拦截游戏点击。此浮窗已包含在 0.3.2 EXE 中。

对局浮窗等待公开回合／阶段开始信号后显示。游戏切到后台、离开对局或暂停读取时隐藏。准备页状态图标仅在准备页显示。

## 读取与联动启动

- 自有只读后端：默认启用，检查游戏版本后读取公开信息。
- Untapped.gg 兼容后端：需要本机安装兼容的读取模块，可在设置中填写其绝对路径；本项目不分发该模块。
- “打开 MD助手时一同启动 Untapped.gg”默认关闭。切换到兼容后端并保存时，会询问是否启用此选项；它控制后续启动行为。找不到程序或启动失败时会提示手动启动。

首次下载卡片属性和卡图需要网络；已缓存资料可复用。数量修正、怪兽数值、库存和牌组核对均在主界面完成，修改的是助手记录，不修改游戏。

助手启动及运行期间会自动检查卡片资料：缓存超过24小时自动更新；当前牌组或公开记录出现缺失资料时提前更新。同类自动请求至少间隔1小时，失败后自动重试并保留缓存。设置中的“更新卡片属性”可随时手动更新。新卡收录时间取决于资料源同步进度，卡图与效果详情仍按需获取。

## 数据与边界

仅读取公开信息，不读取对方未公开身份，不注入或改写游戏，不自动操作游戏。缺少卡表、属性、完整记录或读取过期时，会提示等待或核对，不应把候选信息当成确定结论。

便携版配置与卡组缓存位于 %APPDATA%/md-cannon-assistant，自动展开的运行文件位于 %LOCALAPPDATA%/md-cannon-assistant/portable。源码运行的数据位于 local-data，测试模式使用 test-results/app-data。

打包不包含私人牌组、对局记录、测试结果或 Git 元数据。

## 源码开发

安装项目依赖后执行：

~~~sh
pnpm install
pnpm run build
pnpm start
~~~

工作区也可通过“启动助手.cmd”启动已构建程序。日常修改只构建；需要交付时运行：

~~~sh
pnpm run package:portable
~~~

单文件 EXE 输出到 release，打包中间文件位于 local-data/portable-build。打包要求 Windows x64、Electron 运行环境及 .NET Framework 编译器。

针对性测试可运行：

~~~sh
node --test --test-isolation=none tests/sidebar-layout.test.mjs tests/display-settings.test.mjs tests/preparation-indicator.test.mjs tests/overlay-style.test.mjs
~~~

scripts 下提供设置、模块浮窗、准备页指示器和侧栏重启的 Electron 测试脚本。部分环境限制创建子进程，会返回 spawn EPERM；单元测试通过不等于实窗验收。当前新界面与联动启动仍需实机确认。

## 常见问题

- 更新后界面没变化：先从托盘退出旧助手，再运行新 EXE 或工作区启动脚本。
- 不显示侧栏：检查侧栏模块是否开启，或在主界面点击“显示信息侧栏”。
- 不显示对局浮窗：确认对应开关开启、游戏在前台、读取未暂停且已收到决斗开始信号。
- 无法读取：检查后端、支持版本及主界面诊断信息；不要沿用过期计算结果。
