# MD助手

供个人使用的 Windows PC 版《游戏王 Master Duel》联栗炮计算器，以独立侧栏与游戏窗口并排显示。当前版本为 0.2.0，提供包含 Electron 运行环境的 Windows x64 便携 ZIP；自动读取仍依赖目标电脑上的兼容读取模块。

本地最新版：`release/md-cannon-assistant-0.2.0-win-x64-1792390318951.zip`。完整解压后运行 `MD-Assistant.exe`；无需 Node.js。公开记录、紧凑300px侧栏、浅深主题均已包含。[下载 v0.2.0 正式发行版](https://github.com/414226297/yugioh-md-calculator/releases/tag/v0.2.0)。

## 解决什么问题

使用《联栗炮固定式》时，需要同时核对双方手牌与场上的卡片总数、对方怪兽的等级或阶级，以及自己额外牌组与除外区的可用材料。助手读取这些信息，计算能同时满足两段数值条件的组合，减少对局中的心算和库存核对。

计算规则：

- 初次除外：两只同阶超量的阶级之和，加上一只融合的等级，等于双方手牌与场上卡片总数，即 `2 × 超量阶级 + 融合等级 = 总数`。
- 后续返回：一只超量的阶级，加上一只融合的等级，等于对方所选表侧怪兽的等级或阶级。可用材料包含此前已在除外区的已确认表侧卡片，以及本次拟除外的卡片。

程序核对数值和已知库存，不模拟全部发动限制、连锁、无效等规则；实际发动与选卡由用户在游戏中完成。

源码新增盖牌跟随浮窗：提示位于盖牌内侧下沿，随游戏窗口移动和缩放，游戏进入后台或最小化时隐藏；设置可切换回侧栏并微调位置。该功能尚未包含在已发布的 v0.2.0 中，特殊画面比例需实机核对定位。

## 主要功能

- 在支持的排位或活动准备页面识别当前选中的牌组，核对完整卡表后自动用于下一场对局；切换已知牌组时同步更新。也支持从编辑界面首次读取及手动核对。
- 显示双方手牌、场上四项数量与合计，并提供修正入口。
- 将对方表侧怪兽的等级和阶级去重后显示为小方块；相同数字的星数与阶级分别显示。
- 新增“对方已公开手牌”：读取期间看到游戏公开展示的手牌后，记录卡名和已知张数，展示关闭而未离手时保留。点击卡名可查看卡图、中文效果与类型、属性、等级、攻守等资料；待确认条目同样可查看。首次查看需联网，文字资料缓存在本机，图片失败不妨碍阅读效果，Esc或右上角×关闭。此功能已包含在本地0.2.0便携包中。
- 根据两段条件和可用材料数量给出紧凑数字方案；需要此前已除外材料时，可展开查看返回组合。
- “对方盖放魔陷”显示数量、区域及公开信息推断的候选；只在证据充分时标为可确定，未记录来源的盖牌显示未知。盖牌公开发动后，校正原来的手牌离手记录，避免已使用陷阱残留。中途启动不会读取盖牌身份；候选可点击查看卡片资料。
- 公开检索和公开手牌后的盖放支持位置查询：点击区域查看该位置全部候选，点击卡名查看所有可能位置。公开破坏或发动后同步移除、收窄记录；有其他未知手牌时，检索后立即盖放也只标为可能。
- 公开情报中的卡名旁标记“怪兽／魔法／陷阱”。离手统一按可关联的公开日志卡名和区域移动处理；已公开卡返回牌组等隐藏区域也会扣除，不需要按单张卡效果适配。没有逐卡公开身份的批量移动保持待确认。
- 根据已识别的移动日志更新额外牌组、除外区库存，按融合等级和超量阶级汇总已确认的除外卡片。
- 提供数量、怪兽数值和库存核对，以及暂停、重连、恢复自动读取、窗口尺寸设置与本地诊断功能。
- 数据过期、日志缺失、库存不一致或场面尚未稳定时提示核对，不输出依赖未知数据的确定方案。

## 安装方法

### 便携版：解压运行

1. 获取 `release/` 下对应版本的 `md-cannon-assistant-*-win-x64-*.zip`，将整个文件解压到普通文件夹。不要直接在压缩软件里运行。
2. 双击解压目录中的 `MD-Cannon-Assistant.exe`。这条启动方式不需要安装 Node.js、pnpm 或 Codex，也不依赖原开发电脑的目录。
3. 自动读取需目标电脑安装 MD 和兼容的 Untapped Companion 原生模块。程序查找当前用户与系统的常见安装位置；未找到时会明确提示，可在设置里填写这台电脑的 `.node` 路径。
4. 首次运行需联网获取公开卡片属性；没有缓存且下载失败时，不会产生确定的计算方案。
5. 便携版运行数据保存在当前用户 `%APPDATA%\md-cannon-assistant`，不会把开发者的牌组、设置或历史对局带到新电脑。

ZIP 旁的 `.sha256` 文件可用于校验下载完整性。便携包不包含第三方读取模块；无法承诺任意游戏或模块版本都能准确读取。当前实机验证的是 Unity `6000.0.61f1`，特殊等级/阶级变化等效果仍需人工核对。

0.1.1 修复了空白配置下卡片属性下载失败、导致已读取牌组不能显示获取成功的问题。使用0.1.0便携版时请换用新包；若显示“卡组已读取 · 属性待获取”，点击牌组状态进入核对页面，可查看下载结果并重试“更新卡片属性”。

### 从源码运行的条件

1. Windows PC 和已安装的 MD；本机开发验证环境为 Windows 10 x64、Node.js 24.19.0。
2. Node.js、pnpm，以及可正常运行的 Electron 依赖。
3. 本机已有兼容的 Untapped Companion 原生读取模块。项目不包含该模块，单独安装项目依赖不能替代它。默认读取路径为：

   ```text
   %LOCALAPPDATA%\Programs\untapped-companion\resources\app.asar.unpacked\node_modules\untapped-scry\lib\binding\napi-v5\untapped-scry.node
   ```

   路径可在助手设置中修改。本机读取配置使用 Unity 版本 `6000.0.61f1`；游戏或第三方模块更新后可能需要重新适配，不保证任意电脑和版本都能直接使用。
4. 安装依赖、首次下载卡片属性时需要联网；之后可使用本地属性缓存。没有完整属性数据时，计算会提示待核对。

### 从源码准备并启动

在项目根目录打开终端，运行：

```powershell
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

需要保留 `node_modules` 和生成的 `dist` 目录；Electron 可执行文件也必须下载完整。若安装工具提示需要批准依赖构建，请仅为需要的 Electron 安装步骤完成相应批准。

完成依赖安装和构建后，也可双击根目录的 `启动助手.cmd`。它优先使用 PATH 中的 Node.js；找不到时使用项目已安装的 Electron 自带运行时，不依赖 Codex。修改源码后应重新运行 `pnpm run build` 并重启助手。

### 制作可分享的 ZIP

在已安装开发依赖的 Windows x64 电脑中运行：

```powershell
pnpm run package:portable
```

产物位于 `release/`。打包采用白名单，仅包含官方 Electron 运行环境、项目编译结果、许可与使用说明。不会打入 `.git`、依赖源码目录、个人运行数据、牌组缓存、测试截图或诊断日志；请分享生成的 ZIP，而不是直接压缩整个开发目录。

## 使用方法

1. 启动 MD 和助手，将游戏窗口放左侧、助手放右侧；根据屏幕空间手动调整窗口。
2. 进入排位或支持的活动准备页面并选择牌组，等待助手显示“卡组获取成功”。切换牌组后会自动重新核对；准备页面只展示牌组状态，不显示对局计算方案。
3. 结束对局返回准备页面后，助手重新识别本次所选牌组，无需每场打开编辑页面。首次没有完整卡表、或牌组已修改而卡表尚未更新时，打开一次编辑页面，再返回准备页面。没有有效记录时会显示“已识别牌组 · 卡表待获取”，不会沿用旧牌组。
4. 场面稳定后，参照数量表、对方数值方块及方案，在游戏中自行操作。发生抽卡、召唤或连锁时，应等待数据刷新并再次核对。
5. 读数不符时使用对应的“修正”或除外区的“核对”。库存修正后的总数必须与读取到的区域总数一致；除外卡须确认表侧才可作为返回材料。手动修正会保持，直到恢复自动读取、离开对局或进入新局。
6. 断开时检查 MD、读取模块路径与版本配置，可使用“重新连接”。设置中的“保存本地诊断”会写入运行数据目录的 `diagnostic.json`，导出的错误信息会隐藏本地绝对路径。

中途接入、未知移动或不能确认表里状态时，助手可能要求手动核对。等级、阶级被特殊效果改变等场景尚未全面实测，应以游戏实际显示为准。

公开手牌记录需要助手在展示发生时持续运行；不会读取隐藏手牌的身份，也不能在退出整个助手后补回此前未捕获的展示。当前开发版使用中文卡片库，启动时自动迁移旧英文缓存，下载失败时保留已有缓存并提示重试。换回合、普通文字日志和短暂刷新不清空记录；暂停或短暂读取异常时，卡名保留在“曾公开 · 是否仍在手中待确认”区域。同一局恢复读取后，核对连续日志再恢复确认状态。匿名盖放、丢弃、未知动作、数量矛盾或日志重置会把无法确认的部分转为待确认，不能将这些条目当作确定仍在手中的牌。完整重新展示会替换旧记录；手牌稳定归零、离开对局或新对局会清空。只展示或发动效果但没有离手不会视为使用完。已完成全部手牌公开/隐藏的字段对照与保存快照离线回放；修复后连续实际换回合、短暂检索展示及逐张离手仍待实机验收。

准备页面读取优先使用游戏内存中的完整卡表；缺失时核对助手的 `decks.json`，也可读取本机 `%APPDATA%\untapped-companion\ygom\decks.json` 中已有的个人牌组记录。缓存必须与当前选中牌组的身份和修改时间一致；活动名称的语言差异不作为身份依据。这些个人记录不会随软件打包。新牌组无完整记录时仍需首次加载，单靠名称不能还原卡表。排位已完成两副牌组切换实测；活动按实际界面路径读取，目前重点验证决斗者杯，租借牌组与其他活动不保证已适配。

## 输入输出示例

以下是场面与计算结果示例，数据由游戏读取或在助手中核对修正，并非命令行输入格式。

### 示例一：两段条件均满足

输入场面：

| 区域 | 我方 | 对方 |
| --- | ---: | ---: |
| 手牌 | 1 | 2 |
| 场上 | 4 | 2 |

对方有一只表侧 5 阶怪兽；额外牌组有两只可用的 4 阶超量和一只 1 星融合；此前除外区没有可用材料。

助手显示合计 **9**、对方数值 **5阶**，并给出：

```text
方案 1
除外自己的：2 × 4阶超量 + 1星融合
选择对手场上的：5阶怪兽
```

此时 `4 + 4 + 1 = 9`，后续可返回其中一只 4 阶超量与 1 星融合，满足 `4 + 1 = 5`。

### 示例二：只能满足初次除外条件

输入场面：双方手牌与场上合计 **11**，对方仅有可匹配的 **5阶**怪兽；额外有两只 4 阶超量和一只 3 星融合，此前除外区没有可用融合或超量。

虽然 `4 + 4 + 3 = 11`，但 `4 + 3 = 7`，无法匹配 5 阶目标。助手显示 **“当前无匹配组合”**，不会把只能完成初次除外的组合当成完整方案。

## 数据与功能边界

- 源码运行的数据保存在 `local-data/`；便携版数据保存在当前用户 `%APPDATA%\md-cannon-assistant`。本项目下载公开卡片属性；点击已公开手牌时，按该卡密码向百鸽查询资料并从其CDN加载卡图，不上传完整牌组或对局日志；第三方原生读取模块并未接受完整网络审计。
- 仅支持 Windows PC；不提供手机、主机适配、自动游戏操作、完整图像识别或完整规则模拟。
- 当前开发版卡片属性来自第三方中文数据库；旧0.1.2发行包及中文更新失败时保留的旧缓存仍可能显示英文。
- 项目不附带第三方读取模块，不代表可以直接将该模块随项目分发。

## 开发与验证

```powershell
pnpm run typecheck  # TypeScript 检查
pnpm test          # 单元测试，先运行 pnpm run build
pnpm run test:ui   # Electron 界面测试，不连接游戏
pnpm run test:all  # 构建、全部单元测试与界面测试
```

`scripts/test-live-*.mjs` 为需要 MD 配合的专用实机验收脚本。其中 `test-live-duel.mjs --initial` 要求双方起始手牌各5、场上各0、额外15、除外0；`--resolved` 要求本局完成一次除外3张额外、返回其中2张的指定联栗炮场景，不能用于任意场面。`scripts/check-live.mjs --deck` 也专用于实测的40张主牌、15张额外、13种额外牌组样例。

便携包生成后，可用 `node scripts/test-portable.mjs <ZIP路径>` 检查实际解压、全新用户配置、中文空格路径启动及私人数据排除。此检查验证打包程序的启动与缺失模块处理，不能代替另一台电脑上的实机对局验收。

`node_modules`、`dist`、`local-data`、`test-results`、`.pnpm-store` 和 `release` 已由 Git 忽略。详细需求见 [PRD.MD](PRD.MD)，开发记录见 [docs/PROGRESS.md](docs/PROGRESS.md)，验收证据及覆盖范围见 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。

### 系统托盘

点击最小化或关闭按钮会隐藏主窗口，助手继续运行。点击右下角系统托盘的 MD助手图标恢复窗口；右键菜单选择“退出 MD助手”可彻底退出。游戏浮窗仍按游戏前台状态显示。
