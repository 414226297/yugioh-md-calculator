# MD助手

**公开情报记录 · 盖牌悬浮提示 · 联栗炮计算**

面向 Windows PC 版《游戏王 Master Duel》的个人辅助工具。用紧凑侧栏整理对局公开信息，在对方盖牌上显示提示，并根据场面与材料库存计算《联栗炮固定式》的可用组合。

[下载 v0.3.0](https://github.com/414226297/yugioh-md-calculator/releases/tag/v0.3.0) · [问题反馈](https://github.com/414226297/yugioh-md-calculator/issues) · [MIT 许可证](LICENSE)

> 本页介绍 **v0.3.0 正式发行版**。便携包内置运行环境，无需安装 Node.js；自动读取需要本机已有兼容的 Untapped Companion 原生读取模块，发行包不包含该模块。后续开发中的“对方手牌区类型浮窗”不属于本版。

## 功能一览

| 功能 | v0.3.0 的表现 |
| --- | --- |
| 公开手牌记录 | 在侧栏显示对方已公开且可确认仍在手中的卡名、类别和张数，点击查看资料 |
| 盖牌悬浮提示 | 在对方盖放魔陷内侧下沿显示类型、未知或变动提示，跟随游戏窗口移动和缩放 |
| 卡片报告 | 点击盖牌提示查看卡图、中文效果及类别；多个候选可切换查看，使用 MD 风格素材与字体 |
| 联栗炮计算 | 结合双方手牌与场上总数、对方等级／阶级、额外牌组及表侧除外材料，给出匹配方案 |
| 牌组识别 | 支持的准备页面自动核对所选牌组；提供首次加载和手动核对入口 |

## 运行依赖

**v0.3.0 尚不是完全独立的版本。** 便携包已包含 Electron 运行环境，无需安装 Node.js、pnpm 或 Codex，但自动读取对局仍需要：

- Windows 版《游戏王 Master Duel》。
- 本机兼容的 `untapped-scry.node` 原生读取模块，通常通过安装 Untapped.gg Companion 获得。助手会查找该模块，也可在设置中指定路径。
- 首次获取卡片资料及加载卡图所需的网络连接。

**发行包不附带 Untapped 读取模块；缺少模块时无法自动读取对局。** 单独提取模块、脱离 Untapped 安装环境后的完整运行尚未验证。该模块为第三方组件，再分发许可尚未确认，不属于本项目 MIT 授权范围。

## 下载与启动

1. 启动 MD。助手会尝试查找本机读取模块；如果提示缺失，在设置中填写兼容 `.node` 文件的完整路径。
2. 首次运行保持联网，等待公开卡片属性下载完成。
3. 在支持的排位或活动准备页面选择牌组，等待标题栏显示“卡组获取成功”，再进入对局。

首次没有完整卡表或修改牌组后，可能需要打开一次游戏内牌组编辑页面，再返回准备页面。已识别牌组但缺少卡表时，助手会提示核对。


## 对局中如何使用

### 公开手牌：记录已经看到的信息

助手在公开展示发生时记录卡片。只展示或发动效果但仍留在手中，记录继续保留；根据可关联的公开日志，召唤、盖放、丢弃、返回牌组等离手动作会扣除记录。同名多张按已知张数显示，重复展示不会重复累计。

无法确定离手卡名或日志不完整时，受影响记录会列为候选。助手需要在公开事件发生时运行，不能在中途启动或完全退出后补回未捕获的展示，也不会读取未公开手牌的身份。

### 盖牌：点击提示，查看身份或候选

浮窗只覆盖对方五个魔陷区的里侧卡。场地区不参与记录，表侧永续等卡片不显示盖牌浮窗；场地魔法不会列入普通魔陷区的盖放候选。

| 提示 | 含义 |
| --- | --- |
| 怪／魔／陷 | 公开证据足以确定身份时，显示对应类别；类别缺失时显示“卡” |
| 未知 | 身份未确定，点击可查看已有候选；也可能暂无候选 |
| 变动 | 盖牌位置发生变化，原位置与身份的对应关系不能继续确定 |

点击提示打开左侧卡片报告；多个候选在报告下方列出，点击名称切换。点击场上其他位置关闭报告。候选可能在多个区域重复出现，不能将每个候选视为该区域的确定卡片。

游戏最小化或进入后台时，浮窗一并隐藏。位置按游戏画面比例计算；特殊镜头或宽高比可能偏移，可在设置中微调，也可将“盖牌显示”切回“侧栏五格”。

### 联栗炮：同时核对两段数值条件

助手检查以下条件，并计入已知可用材料库存：

```text
初次除外：2 × 同阶超量的阶级 + 融合等级 = 双方手牌与场上卡片总数
后续返回：1 只超量的阶级 + 1 只融合的等级 = 对方目标怪兽的等级或阶级
```

例如总数为 **9**，对方有 **5 阶**怪兽，额外牌组有两只 **4 阶超量**与一只 **1 星融合**：初次满足 `4 + 4 + 1 = 9`，后续满足 `4 + 1 = 5`。此前已确认的表侧除外材料也会参与返回方案计算。

场面处理中请等待刷新。读数不符时，可使用“修正”或库存“核对”；手动修正保持到恢复自动读取、离开对局或进入新局。程序核对数值与库存，实际发动、选卡和完整效果处理由玩家在游戏内完成。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示需要 Node.js | 通常是运行了源码启动脚本。普通使用请下载发行版 ZIP，解压运行 `MD-Assistant.exe` |
| 未找到读取模块 | 检查本机兼容模块是否存在，并在设置中核对路径；仅安装项目依赖不能替代它 |
| 卡组属性待获取 | 保持联网，在设置中点击“更新卡片属性”；卡表缺失时先打开游戏内牌组编辑页面 |
| 浮窗没有显示 | 确认游戏在前台、存在对方盖放魔陷、读取未暂停且数据未过期，并检查“盖牌显示”设置 |
| 公开手牌没有浮窗 | v0.3.0 的公开手牌显示在侧栏，手牌区类型浮窗尚未包含在本版 |
| 数据不符或连接中断 | 核对游戏与模块版本，使用修正、重新连接或保存本地诊断 |

## 数据与兼容范围

- 支持 Windows x64。游戏版本、读取模块、活动及特殊效果会影响读取结果；排位和部分活动已有实测，租借牌组及所有效果尚未全面覆盖。
- 卡片属性与中文资料来自第三方公开数据库，卡图需要联网加载；文字资料有本地缓存。项目自身的查询不上传完整牌组或对局日志，第三方原生模块未做完整网络审计。
- 便携版配置和缓存保存在 `%APPDATA%\md-cannon-assistant`，源码运行数据保存在 `local-data/`。发行包不包含开发者的牌组、配置、诊断日志和对局记录。
- 数量矛盾、匿名移动、日志缺失或读取异常可能影响记录。程序提供核对入口，不提供自动游戏操作或完整规则模拟。

## 从源码运行

需要 Windows、Node.js、pnpm，以及本机兼容的读取模块。开发验证使用 Node.js 24.19.0。

```powershell
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

完成依赖安装后，也可使用根目录的 `启动助手.cmd`。修改源码后重新构建并重启助手。源码分支可能含未发布功能；如需复现本页版本，请使用 `v0.3.0` 标签。
